## 二、当前实现分析

### 2.1 核心架构

当前 MCTS 遵循标准 UCT（Upper Confidence Bound for Trees）算法，分四阶段迭代执行：

```
Selection → Expansion → Simulation → Backpropagation
```

### 2.2 各阶段实现现状

#### Selection（选择阶段）

使用标准 UCB1 公式选择子节点：

```cpp
double MCTSNode::getUCT(double c_puct) const {
    if (visit_count == 0) return infinity;
    double exploration_term = c_puct * prior * sqrt(N(parent)) / (1 + N(s,a));
    return Q(s,a) + exploration_term;
}
```

**问题**：固定 `c_puct = 1.4142`，无法根据游戏阶段自适应调整探索力度。

#### Expansion（扩展阶段）

节点扩展时根据位置分配先验概率：

| 位置类型 | 先验权重 | 说明 |
|----------|----------|------|
| 角部 | 3.0 | 最有利位置 |
| 边部 | 1.5 | 次有利位置 |
| 诅咒格（角部相邻） | 0.1 | 最不利位置 |
| 其他 | 1.0 | 中性位置 |

**问题**：先验过于简单，没有利用更丰富的棋型知识。

#### Simulation（模拟阶段）

混合策略：
- 空位数 > 12：使用静态评估器选择最佳落子 + 小噪声
- 空位数 ≤ 12：纯随机模拟直到终局

**问题**：
- 评估器精度有限（MAE 约 5-10 子）
- 没有利用终局完美读取
- 模拟质量受限于评估器

#### Backpropagation（反向传播阶段）

标准交替符号反向传播：

```cpp
while (current != nullptr) {
    current->visit_count++;
    current->value_sum += value;
    value = -value;
    current = current->parent;
}
```

**问题**：没有虚拟损失（Virtual Loss）机制，多线程下存在路径重复选择问题。

### 2.3 关键性能指标

| 指标 | 当前值 | 理论最优 | 瓶颈 |
|------|--------|----------|------|
| 模拟速率 | 1,186 K/s | ~5000 K/s+ | 内存分配开销 |
| 每次模拟耗时 | ~843 ns | ~200 ns | 评估函数调用 |
| 模拟次数/步 | 1000 | 5000+ | 单线程瓶颈 |
| 树复用 | 无 | 有 | 需实现哈希表 |

## 三、改进方案详解

以下按优先级排列，所有方案均给出具体实现思路和预期效果。

### 3.1 P0 级：Root 并行化（Root Parallelization）

#### 问题

当前 MCTS 完全串行执行，模拟次数受限于单核速度。

#### 解决方案

采用单轮并行化（Single-Run Parallelization）策略：主线程负责任务分发，多个工作线程各自执行完整的 UCT 搜索流程，通过共享树结构交换信息。

```
┌─────────────────────────────────────────────────────┐
│                    主线程                            │
│  负责任务分发、结果聚合、最佳走子选择                   │
└───────────────────────┬─────────────────────────────┘
                        │ 任务分发
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │Worker 1 │    │Worker 2 │    │Worker N │
    │独立 RNG  │    │独立 RNG  │    │独立 RNG  │
    │完整 UCT  │    │完整 UCT  │    │完整 UCT  │
    └────┬────┘    └────┬────┘    └────┬────┘
         │               │               │
         └───────────────┼───────────────┘
                         ▼
              ┌─────────────────────┐
              │   共享 MCTS 树        │
              │ (原子操作更新节点)     │
              └─────────────────────┘
```

#### 核心实现

**1. 线程池与任务分发**

```cpp
// src/ai/MCTSAI.cpp 新增

class MCTSAI {
private:
    // 并行化相关
    std::vector<std::thread> workers_;
    std::atomic<bool> stop_flag_{false};
    std::atomic<int> active_workers_{0};

    // 线程安全的随机数生成器
    std::vector<std::mt19937> worker_rngs_;
    std::mutex rng_mutex_;

    // 原子操作更新节点统计
    void atomicUpdate(MCTSNode* node, double value) {
        node->visit_count.fetch_add(1, std::memory_order_relaxed);
        // value_sum 使用原子加法（或锁）
        // 注意：反向传播需要特殊处理
    }

    // 工作线程函数
    void workerThread(const Board& root_board);
};
```

**2. 原子操作替代锁**

```cpp
// 使用 C++11 原子变量替代互斥锁
struct MCTSNode {
    std::atomic<int> visit_count{0};
    std::atomic<double> value_sum{0.0};
    double prior = 0.0;
    // ...
};
```

**3. 每个线程独立的 RNG**

```cpp
std::mt19937& getWorkerRNG() {
    std::lock_guard<std::mutex> lock(rng_mutex_);
    return worker_rngs_[get_current_worker_id()];
}
```

#### 预期效果

参考 Emiliano1919/Othello-Engine 在 Apple M1 上的测试数据：

| 配置 | 模拟次数 | 每步耗时 | 相对性能 |
|------|----------|----------|----------|
| 单线程 MCTS | 500 | ~30ms | 1x |
| 单线程 MCTS | 2000 | ~120ms | 1x |
| **并行化 MCTS** | **2000** | **~7ms** | **~17x** |

对于当前平台（假设 x86 多核 CPU），预期提升 4-8 倍。这意味着在相同时间内，模拟次数可以从 1000 提升到 4000-8000。

#### 工作量估算

- 代码量：约 150-200 行
- 难度：中等（主要挑战是线程安全）
- 风险：低（方案成熟，参考实现充分）

### 3.2 P0 级：PUCT 选择策略

#### 问题

标准 UCB1 在 Reversi 这种合法走子较少（平均 ~10 个）的游戏中，探索-利用平衡不够精细。

#### 解决方案

采用 PUCT（Polynomial Upper Confidence Bound for Trees），这是 AlphaGo/AlphaZero 使用的选择公式：

```
PUCT = Q(s,a) + c_puct × P(s,a) × sqrt(N(s)) / (1 + N(s,a))
```

或更精确的 AlphaZero 形式（增加 P(s,a) 调节因子）：

```
PUCT = Q(s,a) + c_puct × P(s,a) × sqrt(N(s)) / (1 + N(s,a) + c_puct × P(s,a) × sqrt(N(s)))
```

#### 核心实现

```cpp
// include/ai/MCTSAI.h 修改 MCTSNode::getUCT

enum class SelectionPolicy {
    UCB1,    // 标准 UCB1
    PUCT,    // AlphaZero PUCT
    PUCT_SIMPLIFIED  // 简化的 PUCT
};

struct MCTSConfig {
    // ... 现有字段 ...
    SelectionPolicy selection_policy = SelectionPolicy::PUCT_SIMPLIFIED;
    double c_puct = 1.4142;
};

double MCTSNode::getPUCT(double c_puct) const {
    if (visit_count == 0) {
        return std::numeric_limits<double>::infinity();
    }
    double parent_visits = parent ? parent->visit_count : 1.0;
    // AlphaZero 风格的 PUCT
    double u = c_puct * prior * std::sqrt(parent_visits) /
               (1.0 + visit_count + c_puct * prior * std::sqrt(parent_visits));
    return getValue() + u;
}
```

#### 预期效果

参考 Emiliano1919/Othello-Engine 的对战测试（各 500 simulations，100 局）：

| 对战配置 | PUCT 胜 | 平局 | PUCT 胜率 |
|----------|---------|------|-----------|
| PUCT(白) vs UCT(黑) | 57-67 | 4-7 | 57-67% |
| PUCT(黑) vs UCT(白) | 64 | 6 | 64% |

PUCT 相比 UCT 胜率提升约 10-20 个百分点。

#### 工作量估算

- 代码量：约 30-50 行
- 难度：低
- 风险：极低（纯算法参数替换）

### 3.3 P1 级：终局完美读取（Endgame Perfect Reading）

#### 问题

当前 MCTS 在终局阶段（空位 ≤ 12）使用纯随机模拟，噪声极大。每增加一次空位，搜索树的宽度就增加约 10 倍，纯随机模拟的信息量远不足以指导决策。

#### 解决方案

当空位数减少到某个阈值以下时，切换到确定性搜索（Minimax + αβ 剪枝），利用已有的 MinimaxAI 实现：

```
┌────────────────────────────────────────────┐
│  搜索选择策略                               │
│                                             │
│  if (empty_squares <= 8):                  │
│      使用 Minimax + AlphaBeta 完美读取      │  ← 确定性，无噪声
│  elif (empty_squares <= 14):               │
│      使用 Minimax + AlphaBeta (深度限制)     │  ← 近似完美
│  else:                                     │
│      使用 MCTS                              │
└────────────────────────────────────────────┘
```

#### 核心实现

**1. 扩展 `AIStrategy` 接口**

```cpp
// include/ai/AIStrategy.h 新增

class AIStrategy {
public:
    // 新增：终局确定性搜索接口
    virtual Move findPerfectMove(const Board& board, int max_depth) {
        return findBestMove(board, SearchLimits::depth(max_depth));
    }
};
```

**2. 在 MCTSAI 中集成**

```cpp
// src/ai/MCTSAI.cpp 修改 simulateWithHeuristic

double MCTSAI::simulateWithHeuristic(Board board) {
    int empty_count = board.getBitBoard().getEmptyCount();

    // 空位 <= 8 时使用 Minimax 完美读取
    if (empty_count <= 8) {
        return simulateWithMinimax(board);
    }

    // 否则继续现有混合策略
    // ...
}

double MCTSAI::simulateWithMinimax(Board board) {
    // 利用已有的 MinimaxAI 进行终局搜索
    static MinimaxAI minimax(MinimaxConfig{.depth = 60}); // 完美读取
    return minimax.evaluateTerminal(board); // 返回 +1/0/-1
}
```

**3. 阶段阈值参数化**

```cpp
struct MCTSConfig {
    // ... 现有字段 ...
    int perfect_reading_threshold = 8;   // 完美读取阈值
    int minimax_fallback_threshold = 14; // Minimax 回退阈值
};
```

#### 预期效果

| 空位数 | 当前方法 | 改进后 | 提升 |
|--------|----------|--------|------|
| 8 | 纯随机（~10^8 种终局可能） | Minimax 完美读取 | **巨大** |
| 12 | 纯随机（~10^10 种终局可能） | Minimax 近似完美 | **显著** |
| 16 | MCTS + 评估器 | MCTS + 评估器 | 不变 |

对于 Reversi 来说，**终局的每一步决策都直接影响最终胜负**，完美读取对胜率的提升将是决定性的。

#### 工作量估算

- 代码量：约 50-80 行
- 难度：中等（需要复用现有 MinimaxAI）
- 风险：低（主要是整合，已有 MinimaxAI 实现）

### 3.4 P1 级：置换表与树复用（Transposition Table & Tree Reuse）

#### 问题

每一步都从零开始构建 MCTS 树，丢弃之前积累的所有信息。如果前后两步有重叠局面，这些计算完全浪费。

#### 解决方案

两个策略配合使用：

**策略 A：置换表（Transposition Table）**

利用 Zobrist Hash 快速识别之前搜索过的局面，复用搜索结果：

```cpp
// include/ai/MCTSAI.h 新增

class TranspositionTable {
public:
    struct TTEntry {
        uint64_t hash;
        double value;
        int depth;
        enum Flag { EXACT, LOWER, UPPER };
        Flag flag;
    };

    void store(uint64_t hash, double value, int depth, TTEntry::Flag flag);
    TTEntry* probe(uint64_t hash);

private:
    static constexpr size_t TABLE_SIZE = 1 << 20;  // 约 100 万条目
    std::vector<TTEntry> entries_;
};

double MCTSAI::probeTT(const Board& board) {
    uint64_t hash = board.getZobristHash();
    auto* entry = tt_.probe(hash);
    if (entry && entry->depth >= current_depth_) {
        if (entry->flag == TTEntry::EXACT) return entry->value;
        if (entry->flag == TTEntry::UPPER && entry->value <= beta) return entry->value;
        if (entry->flag == TTEntry::LOWER && entry->value >= alpha) return entry->value;
    }
    return TT_MISS;
}
```

**策略 B：树复用（Tree Reuse）**

新一步时，保留之前的树结构，将对手的落子对应的子节点作为新的根：

```cpp
// src/ai/MCTSAI.cpp 修改 findBestMove

Move MCTSAI::findBestMove(const Board& board, const SearchLimits& limits) {
    if (root_) {
        // 尝试复用之前的树
        Move last_opponent_move = board.getLastMove(); // 需要 Board 支持

        if (last_opponent_move.isValid()) {
            MCTSNode* opponent_node = root_->findChild(last_opponent_move);
            if (opponent_node) {
                // 复用对手的子树：将其提升为新的根
                root_ = std::unique_ptr<MCTSNode>(opponent_node->extract());
                root_->parent = nullptr;
                // 注意：visit_count 可以适当衰减，避免统计过期
            }
        }
    }
    // ... 其余搜索逻辑 ...
}
```

#### 预期效果

| 场景 | 提升 |
|------|------|
| 连续搜索同一局面 | 几乎零成本复用 |
| 对手走子可预测 | 子树复用，减少 30-50% 搜索量 |
| 搜索深度增加 | 后期每步可利用更多前期积累 |

Emiliano1919 特别指出：这一优化"节省了反向传播到达初始根节点的信息"，同时"减少了反向传播算法的运行量"。

#### 工作量估算

- 代码量：约 100-150 行
- 难度：中等
- 风险：中（需要处理哈希碰撞、老化等边界情况）

### 3.5 P1 级：动态 c_puct 调整

#### 问题

固定 `c_puct = 1.4142` 无法适应游戏的不同阶段：
- 早期：需要更多探索（高 c_puct）
- 中盘：平衡探索与利用（中 c_puct）
- 终局：需要更多利用已有信息（低 c_puct）

#### 解决方案

根据空位数（或步数）动态调整 c_puct：

```cpp
// src/ai/MCTSAI.cpp

double MCTSAI::getDynamicCPuct(const Board& board) {
    int empty = board.getBitBoard().getEmptyCount();

    if (empty > 40) return 1.8;   // 早期：强烈探索
    if (empty > 20) return 1.5;   // 中盘前段
    if (empty > 12) return 1.3;   // 中盘后段
    if (empty > 6)  return 1.1;   // 终局前段
    return 0.8;                     // 终局：利用为主
}
```

或者使用平滑插值：

```cpp
double MCTSAI::getDynamicCPuct(const Board& board) {
    int empty = board.getBitBoard().getEmptyCount();
    double ratio = empty / 60.0;  // 0.0 (终局) 到 1.0 (开局)
    return 0.8 + 1.0 * ratio;     // 线性插值：[0.8, 1.8]
}
```

#### 预期效果

- 早期胜率提升：约 5-10%（更多探索避免局部最优）
- 终局胜率提升：约 3-5%（更精准的决策）
- 整体胜率提升：约 5-10%

#### 工作量估算

- 代码量：约 20-30 行
- 难度：极低
- 风险：低

### 3.6 P2 级：Progressive Widening（渐进式扩展）

#### 问题

当前实现中，节点展开时一次性生成所有子节点。当合法走子较多时（如开局约 10 个），大量未探索的子节点都会返回 infinity 的 UCT 值，导致选择具有随机性。

#### 解决方案

采用渐进式扩展策略：子节点数量随父节点访问次数动态增长：

```
可扩展子节点数 k(n) = floor(α × n^β)
```

其中 α 和 β 为可调参数。例如 α=0.5, β=0.5 时：

| N(parent) | k(n) |
|-----------|------|
| 1 | 0 |
| 4 | 1 |
| 16 | 2 |
| 100 | 3 |
| 400 | 4 |

#### 核心实现

```cpp
// src/ai/MCTSAI.cpp 修改 search 方法

void MCTSAI::search(const Board& board) {
    // ...
    if (current->isLeaf() && !sim_board.isGameOver()) {
        auto valid_moves = sim_board.getValidMoves();

        if (!valid_moves.empty()) {
            // 渐进式扩展：只展开 k(n) 个子节点
            int parent_visits = current->visit_count;
            double alpha = 0.5, beta = 0.5;
            int k = static_cast<int>(alpha * std::pow(parent_visits, beta));

            // 优先展开高先验的走子
            std::vector<double> priors = getPriorProbabilities(sim_board);
            std::vector<size_t> sorted_indices = argsort(priors, std::greater<>());

            int expand_count = std::min(k, static_cast<int>(valid_moves.size()));
            for (int i = 0; i < expand_count; ++i) {
                size_t idx = sorted_indices[i];
                auto child = std::make_unique<MCTSNode>(current);
                child->prior = priors[idx];
                current->addChild(valid_moves[idx], std::move(child));
            }
        }
    }
    // ...
}
```

#### 预期效果

- 减少初期探索噪声（只展开最有希望的节点）
- 提高已有节点的更新频率（更快的收敛）
- 预计胜率提升：约 3-8%

#### 工作量估算

- 代码量：约 40-60 行
- 难度：中等
- 风险：中（参数调优需要实验）

### 3.7 P2 级：Virtual Loss（虚拟损失）

#### 问题

在并行化 MCTS 中，多个工作线程可能同时选择相同的路径，造成冗余探索和锁竞争。

#### 解决方案

在选择阶段引入虚拟损失机制：当一个线程选择某个节点时，临时降低该节点的 UCT 分数：

```cpp
// 修改后的 UCT 公式（带虚拟损失）
// T(s,a) = 正在该分支上探索的线程数
double uct_with_vloss = (N(s,a) * Q(s,a)) / (N(s,a) + T(s,a))
    + c_puct * sqrt(log(N(s) + T(s)) / (N(s,a) + T(s,a)));
```

#### 核心实现

```cpp
// include/ai/MCTSAI.h MCTSNode 新增

struct MCTSNode {
    // ... 现有字段 ...
    std::atomic<int> virtual_loss{0};  // 新增：虚拟损失计数
};

// src/ai/MCTSAI.cpp

void MCTSAI::workerThread(const Board& root_board) {
    while (!stop_flag_) {
        // Selection 阶段：应用虚拟损失
        MCTSNode* selected_node = selectionWithVirtualLoss(board);

        if (selected_node) {
            // 增加虚拟损失
            selected_node->virtual_loss.fetch_add(1, std::memory_order_relaxed);
            active_workers_++;

            // 执行 simulation
            double result = simulateWithHeuristic(board);

            // 反向传播
            backpropagate(selected_node, result);

            // 移除虚拟损失
            selected_node->virtual_loss.fetch_sub(1, std::memory_order_relaxed);
            active_workers_--;
        } else {
            // 无可用节点，等待
            std::this_thread::sleep_for(std::chrono::microseconds(10));
        }
    }
}

double MCTSAI::getUCTWithVirtualLoss(const MCTSNode* node, double c_puct) {
    int vloss = node->virtual_loss.load(std::memory_order_relaxed);
    int N = node->visit_count + vloss;
    double Q = (N > 0) ? node->value_sum / N : 0.0;
    int parent_visits = node->parent ? node->parent->visit_count : 1;

    double u = c_puct * node->prior * sqrt(parent_visits) / (1 + N);
    return Q + u;
}
```

#### 预期效果

| 线程数 | 无虚拟损失 | 有虚拟损失 |
|--------|------------|-----------|
| 1 | 基准 | ~0% 变化 |
| 2 | 冗余 30-40% | ~10% 冗余 |
| 4 | 冗余 50-60% | ~15% 冗余 |
| 8 | 冗余 70-80% | ~20% 冗余 |

### 3.8 P3 级：评估函数增强（Pattern-Based Evaluation）

#### 问题

当前静态评估器使用简单的 8×8 位置权重矩阵，MAE 约 5-10 子。相比之下，Egaroucid 使用的 Pattern 评估法 MAE 约 3.5 子。

#### 解决方案

采用 Logistello/Egaroucid 开创的 Pattern 评估法：

**1. 特征 Pattern 定义**

```cpp
// include/ai/PatternEvaluator.h 新增

namespace Reversi {

// 棋型特征（参考 Egaroucid 的 64 个特征）
enum class PatternType {
    CORNER_3x3,       // 角部 3x3 模式
    EDGE_5,           // 边部 5 格模式
    DIAGONAL_4,       // 对角线 4 格模式
    STABILITY,        // 稳定性模式
    MOBILITY_8        // 灵活性 8 格模式
};

struct PatternFeature {
    uint64_t mask;     // 模式掩码
    uint64_t bits;    // 当前棋型
    int weight;        // 权重（通过训练获得）
};

// 预定义特征（考虑旋转/翻转后共 64 个）
const std::vector<PatternFeature> PATTERN_FEATURES = {
    // 角部模式 (8个对称)
    PatternFeature{.mask = 0x0000000000000381ULL, .weight = 100},
    // 边部模式 (16个对称)
    PatternFeature{.mask = 0x0000000000180330ULL, .weight = 20},
    // ... 更多模式
};
}
```

**2. 差分计算**

```cpp
// 每步只更新变化的部分，而非全盘重算
int PatternEvaluator::evaluateIncremental(const Board& board,
                                          const Move& last_move,
                                          int previous_score) {
    int delta = 0;
    // 放置的棋子影响哪些特征
    for (int feat_idx : features_affected_by_square[last_move.row * 8 + last_move.col]) {
        delta += evaluateFeature(board, feat_idx) - previous_feature_values_[feat_idx];
        previous_feature_values_[feat_idx] = evaluateFeature(board, feat_idx);
    }
    // 翻转的棋子影响哪些特征
    for (const auto& flipped : board.getLastFlipped()) {
        for (int feat_idx : features_affected_by_square[flipped]) {
            delta += evaluateFeature(board, feat_idx) - previous_feature_values_[feat_idx];
            previous_feature_values_[feat_idx] = evaluateFeature(board, feat_idx);
        }
    }
    return previous_score + delta;
}
```

**3. 训练流程**

```cpp
// 训练脚本（Python 或独立工具）

// 2. 使用 Adam 优化器梯度下降
// 3. 每个 phase (步数) 有独立权重
// 4. 输出 C++ 权重表供运行时使用
```

|----------|-----|-------------|
| 位置权重矩阵 | ~7 子 | 基准 |
| Pattern 评估（未训练） | ~5 子 | +3-5% |

### 3.9 P3 级：AlphaZero 风格神经网络

#### 方案概述

这是所有改进中效果最显著但工作量最大的方案。参考 [aroellin/reversi](https://github.com/aroellin/reversi) 的实现，训练一个 Policy-Value Network 来替代当前的随机模拟和静态评估器：

```
┌─────────────────────────────────────────────────┐
│           Policy-Value Network                  │
│                                                 │
│  输入层: 6 通道 × 8×8 棋盘特征                  │
│    ├─ 通道0: 当前玩家棋子                        │
│    ├─ 通道1: 对手棋子                          │
│    ├─ 通道2: 空位                              │
│    ├─ 通道3: 合法性掩码                        │
│    └─ ...                                      │
│                                                 │
│  主干: Conv2d(6→64) + BatchNorm + ReLU         │
│       + 4× ResidualBlock(64→64)                │
│                                                 │
│  ├─ Policy Head: Conv2d → Flatten → Linear(4096→65) │
│  │   输出: 65 维概率向量 (64个落子 + 1个pass)   │
│  │                                                   │
│  └─ Value Head: Conv2d → Flatten → Linear(4096→1) → Tanh │
│      输出: [-1, +1] 胜率估计                      │
└─────────────────────────────────────────────────┘
```

#### 训练流程

```
第 1 轮: 从随机初始化开始
    ↓
自对弈生成数据 (MCTS 10 simulations)
    ↓
训练网络 (拟合策略概率 + 终局胜负)
    ↓
第 2 轮: 新网络自对弈生成数据
    ↓
新网络 vs 旧网络对战
    ↓
胜出则替换，迭代 30+ 轮
    ↓
第 30+ 轮: 切换到 MCTS 100 simulations
```

#### 预期效果

aroellin/reversi 的实验表明，经过 30+ 轮训练后：
- MCTS 50 sims 的胜率 vs MCTS 100 sims 可达 45-55%（接近）
- 远超任何纯静态评估的 MCTS 实现

#### 工作量估算

- 代码量：500-1000 行（网络）+ 训练框架 300-500 行
- 难度：极高（需要 PyTorch/C++ 网络推理集成）
- 风险：高
- **建议**：作为长期研究目标，不建议在当前项目周期内实现
